# Evaluation sets

The manifests, jobs, families and confirmed labels of the public sets (docs/evalsets.md). Images
live in [wafflery-evalsets](https://github.com/markhayden/wafflery-evalsets) and are placed here
by `squint sets fetch --set <id>`; `squint sets check evalsets/` checks everything that is
checkable by code, and each set's `seal.toml` binds its content to the owner's attestation.

**Review log.** Every generated image, kept or replaced, is in the owner's construction record
for the set (owner storage, never published), with generator, model, prompt, seed where the API
has one, every edit instruction, and the hash of each file. For pets-v1: 30 images kept (10
references, 20 candidates), 2 candidates replaced by `rebuild` before the review, 0 struck. For
scenes-v1: 25 kept, 0 replaced, 0 struck. For people-v1: 25 kept, 8 candidates replaced (planted
defects an edit left out, redrawn by generation; two defect kinds swapped), 0 struck. For
stills-v1: 20 kept, 2 replaced, 0 struck. For packshots-v1: 25 kept, 0 replaced, 0 struck. For
the five adversarial sets: 16 kept, 1 replaced, 0 struck. The baseline reports the adversarial
sets separately from the dev sets. No
judge model or tool of the harness ran on any item before labelling. The assistant that built the
set viewed the contact sheets of this dev set to report on edit quality; it never views a blind
set's items. The exception is blind-v3: the owner's review found edits that had not taken and sources that did not match their descriptions, and the agent fixing them saw about 40 items with their labels and ran pixel-difference checks and the segmenter on some. Read its scores on those items as dev, not held out. For blind-v3: 167 kept, 10 replaced, 1 struck.
